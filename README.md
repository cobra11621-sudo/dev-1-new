# Dev-1-new

`D:\ddd\dev-1-new`은 `D:\ddd\dev-1`의 화면과 이동 흐름을 참고해 **Flet/Python 없이 Kotlin + Jetpack Compose + Android 네이티브 서비스**로 다시 구현하는 프로젝트입니다. Dev-1의 기존 코드는 수정하지 않습니다.

## 현재 구현

- 출근·퇴근·병원 3개 탭과 단일 네이티브 경로 상태.
- SQLite에 저장되는 이동 상태를 Compose 화면, foreground tracking service, 알림이 함께 사용.
- 첫 버스 탑승예정과 독립 병원 경로 시작은 화면에서 선택하고, 후속 버스·KTX는 GPS 조건에 따라 자동 진행.
- 지하철 탑승은 수동 버튼 한 번으로 처리하고, 해당 시각에 가장 가까운 전체 시간표 CSV의 열차 번호와 경로 역별 시각을 고정한 뒤 시간표만으로 진행·자동 하차.
- 대전 514번과 대구 버스 API 파싱, 차량별 ETA·남은 정류장 묶음, 저장 API 키 Android Keystore 암호화.
- 화면이 꺼져도 위치를 받는 foreground service와 공유 상태 기반 진행 알림/Now Bar renderer.
- KTX 열차번호·출발/도착 시각·승차홈·호차·좌석 수동 입력, 취소, 여정 재개, 출퇴근 날짜가 바뀔 때 미완료 이동을 정리하는 상태 전환.
- 퇴근 동구4 짧은 환승 구간은 Dev-1 규칙에 따라 마지막 구간 중간 이후 환승권역에서 유효 GPS 한 번으로 지하철 예정으로 전환.
- 빠른 환승 `6-4`는 출근 지하철 앱 카드에만 표시하며 알림에는 넣지 않습니다.

## 시간표 주의사항

전체 시간표 자료는 Dev-1에서 복사한 열차번호별 CSV를 사용합니다. 하행 `line1_down_20241007.csv`와 상행 `line1_up.csv` 모두 공식 자료의 **2024-10-07 운행계획**과 일치합니다. 대구교통공사 웹 시간표 페이지는 2026-09-16 수정된 최신 첫차·막차/운행간격 정보를 보여 주고 역별 시간표 API도 제공하지만, API 응답은 역별 출발 목록으로 열차번호가 없으며 전체 경로의 같은 열차를 고정하는 CSV와 구조가 다릅니다. 자동으로 열차를 추정해 교체하지 않고, 기존 2024 자료를 유지하면서 앱에 기준일을 표시합니다. 이 자료를 2026년 최신 실시간 시간표라고 주장하지 않습니다.

## 아직 남은 작업

- KTX는 현재 수동 입력 방식으로 유지합니다. API나 공식 시간표 조회로 바꾸는 것은 추후 결정이며, Dev-1 소스에서 확인되지 않은 승차홈 기본값은 사용하지 않습니다.
- SQLite 진단 테이블은 만들었지만, 실제 진단 이벤트/GPS 샘플 기록, 오류 기록 화면, 공유·내보내기는 아직 구현하지 않았습니다.
- Android 빌드와 JUnit 실행은 아직 하지 않았습니다. `D:\ddd\nodelete`에는 Python 가상환경들만 있고 Android 도구는 없습니다. 사용자의 정정에 따라 기본 Android SDK는 `C:\Users\cobra\Android\sdk`로 확인했으며, 플랫폼은 34/35/36, Build-Tools는 28.0.3/34.0.0/35.0.0입니다. `adb.exe`는 SDK 내부에 있지만 전역 `adb`와 `gradle` 명령은 PATH에 없습니다. `D:\ddd\flutter-sdk-home`은 별도 Flutter SDK 위치이며 내부 캐시에도 wrapper 스크립트/JAR이 있지만, dev-1-new에는 wrapper 파일이 없습니다. Dev-1 전용 `D:\ddd\Dev-1\.build-venv`는 별도 환경입니다. 서명키는 사용자 확인상 private 위치에 보관되어 있으며 아직 접근하지 않았습니다. 프로젝트 규칙상 Now Bar 문구 표를 먼저 승인받고 사용자가 빌드를 명시적으로 요청하기 전에는 빌드·설치하지 않습니다.
- 실제 Galaxy S26에서 잠금화면 GPS, 알림 권한, 배터리 제한, Samsung Now Bar 표시를 검증해야 합니다. 현재 상태는 **구현 진행 중**이며 실기기 검증 완료가 아닙니다.

## 설정 및 실행 전 참고

버스 API 키는 앱의 설정 화면에서 사용자가 직접 입력해야 하며 Android Keystore 암호화 저장을 사용합니다. 비밀 키 파일이나 Dev-1의 사용자별 설정 파일은 새 프로젝트로 복사하지 않습니다.
